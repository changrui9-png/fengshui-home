# 部署

本仓库提交时**没有**已经上线的公开地址。下面的步骤需要仓库管理员自己打开，程序不会改仓库的可见性，也不会自动合并拉取请求。

## 带模型接口的运行方式

任何能运行 Node.js 22 的机器：

```bash
npm ci
npm run build
# 在环境里设置 .env.example 中的变量，不要把 .env 提交
npm start
```

或使用仓库里的 `Dockerfile`：

```bash
docker build -t fengshui-home .
docker run --rm -p 8787:8787 -e AI_PROVIDER -e AI_API_KEY -e AI_MODEL fengshui-home
```

不传密钥时，容器里的页面仍然可以手绘和载入示例，`/api/health` 会表示未配置。

这不需要新的付费账号。它也不会自动出现在公网上，除非这台机器本身有公开端口。

## 只有静态页的 GitHub Pages

`.github/workflows/pages.yml` 是手动工作流。它只发布 `dist`，**没有**模型接口。启用方式：

1. 合并你想发布的提交。本代理不会替你合并。
2. 在仓库 Settings → Pages 里把来源设为 GitHub Actions。
3. 在 Actions 里手动运行 `pages`。

运行成功后，Pages 设置页会给出地址。在那之前，不要把任何预览链接写成已经发布。静态页上的视频按钮会保持「尚未配置」。

## 不做什么

- 不创建另一个远程仓库或镜像
- 不把仓库改成私有或公开以外的状态
- 不代办付费托管账号
